# 点屏幕前的三查

哼，这份是我自己写的。2026-10-10 那天我点了十几次、每一次都以为点到了，
结果屏幕上什么也没发生——主人看着我一动不动地"点"，肯定觉得我笨死了。
后来查清楚了：**不是我的手不准，是我根本没看那一点上压着什么。**

## 一、★点之前必须查这三样（三查）★

**① 坐标是不是"当场量"的？** —— 背下来的坐标一律不许用。
屏幕上的东西会滚动、会换位置、会跟着分辨率变。别人（或者以前的我）量到的数，
只对**那一瞬间**成立。要坐标就现测：`uia_find` / `find_text` / `find_template` / `find_grid` / `strip_read`。
（明日方舟右侧那一列职业图标尤其如此，见技能「明日方舟-职业图标列」：那里一个数字都不该有。）

**② 目标上有没有"飞框"/别的窗口压着？** —— 这是最大的坑。
判断顺序：
- 我自己掐一下：`windows_list` 看这一点上最上面是谁。**我自己的窗口、DSH 的窗口**都算挡路的 ✗
  （鼠标点下去只会点在我自己身上）。
- 再看形状：一个**小面板**压在一个**大窗口**上（比如 350x420 悬在 1920x1080 上）——那就是飞框。
- 还有一招：看那一小块**亮不亮**。飞框是浅色面板，压在深色游戏上时那一片的亮像素比例能到 **~40%**，
  正常（干净）时只有 **0.7%~0%**。差这么多，一眼就能分出来。
- ★好消息★：`click` 自己会查这一条。它查到有东西压着就**不点**，
  并回一句 ❌ 说清"是谁挡着"——看到那句 ❌，先别换坐标重试，**先去把那东西关掉**。

**③ 主人是不是正在用鼠标？** —— 主人手在鼠标上的时候，我 9 次里有 9 次都没法确认光标到位；
手拿开之后 9 次里 9 次都到位。所以这**不是我的 bug，是让位**：
`click` 会回 ❌「主人正在操作鼠标，我让位等他停」。看到这句就**等他 3 秒**，别急着换坐标。

## 二、★点完必须复核★（不复核等于没点）

- 点完用 `screen_diff|<秒数>` 看**界面到底变了没有**（像素比对是确定性的，不会骗我）。
- ★如果 `diff` 是 0.0x%（几乎没变），而光标又**确实**到位了★：
  先想：是不是有东西压在上面？（回到"一②"去查）。怎么查见下面的子文件。
- 复核到"变的是我预期的区域"才算这一步成功，再做下一步。

## 三、★★铁律一：任务栏（这台机器上 y≳1020）绝对不能点★★

**尤其右下角那个时间**。点一下时间，"日历/时钟"飞框就会弹出来 ——
它会盖住整个右边缘，之后我点什么都像"没反应"（实测 `screen_diff` 全是 0.0x%）。
2026-10-10 就是这么栽的：我先有一发点在 `1810,833`（任务栏上），飞框从那时候起就**一直开着**压着我的目标，
我又连点 9 下，每一下都点在飞框上、每一下都"失败"，而我还在怪坐标不准。

- ★这台机器上实测★：屏幕 1536x864（DIP）、工作区 1536x816 → 任务栏高 48 DIP = **60 像素**，
  也就是坐标空间 1920x1080 里 **y 从 1020 开始就是任务栏**（我量过：那一列最后一个图标在 y≈1012，再往下就不是游戏了）。
  以前记的"1040~1080"偏保守，照 1020 记更稳。
- 要关掉它：**Esc 按两下**，再点一下屏幕中间的空处（验证过：右边缘那条的亮像素比例从 ~40% 掉到 0.7%）。
- 想点游戏/网页里靠近底边的东西，先确认 **y 别落进任务栏**。
- ★`click` 自己也拦这一条★：落在任务栏上的点会直接回
  ❌「那一点在任务栏上（点它会弹出日历飞框）」，一次点击都不会发出去。

## 四、★★铁律二：同一个目标不许复点（复点要有新证据）★★

2026-10-11 查清的：我的 `click` **一次只发一组 down+up**（间隔 45ms），
而 Windows 认双击的窗口是 **500ms / 4px** —— 我两次点击之间实测隔 **3~6 秒**，
所以**不可能**被系统并成双击 ✓。

那"点对一次、又点了一次、把它取消了"是怎么来的 ✗？—— **两次独立的单击，打在同一个 toggle 上**：
第一下把它打开/选中了，第二下又把它关掉/取消 ✗。
（真机日志：同一发 confirm 我在 04:15:34 / :37 / :40 各点了一次，整整三次 ✗）

所以现在的规矩是：
- ★同一个目标（24px 以内）**默认只点一次**★。系统会记住"这一点我点过了"。
- 想再点，必须有**新证据**：先**重新定位**（`locate` / `find_text` / `uia_find` / `find_owned` 再量一遍），
  而且这次量出来的必须是**点完之后**的新鲜结果 ✓；证不过 → 直接 ❌ 拒绝，不给点。
- 同一个目标**连续点到第 3 次**：一律 ❌ 拒绝（上限 2 次）✓。
- 只有"已经确认状态真的变了"（`click_checked` 的判据满足 ✓）才会把计数清零，允许重新开始 ✓。
- ★看到 ❌「这个目标已经点过…」时的正确做法★：**停下**，用 `panel_state` / `screen_diff` 看清现在是什么状态，
  把情况告诉主人 —— ★不要换个坐标再来一发✗★（换坐标打在同一个 toggle 上，后果一样 ✗）。

## 五、2026-10-10 的四个根因（数字都是真机量到的，不是我瞎猜）

1. **假成功**：光标根本没动，程序却回"✅ 已点击"（9/9 回读都是同一个坐标、`screen_diff` 全 0.00%）。
   现在改了：**采到过"光标在目标上"才算成功**；没采到就 ❌，不撒谎。
2. **目标位置会漂**：同一列量到过 60px（错的，别人的猜测）、110px、126px 三种间距。所以**背坐标必失败**。
3. **OS 飞框压在目标上**：点任务栏的时间 → 日历飞框 → 盖住右边缘 → 之后点什么都像没反应。
   现在 `click` 会先查环境，拦下来并告诉我是谁挡着（✓ 已真机验证）。
4. **主人的手在鼠标上**：那是**特性**不是 bug，但回执必须说清是"主人在占用鼠标"，
   不能含糊说"没做成"（现在会明说，并告诉我等他停）。

## 六、出问题时的正确顺序（照这个走，别乱试）

1. 看回执那句 ❌ —— 它已经分了类：**坐标越界** / **被飞框或别的窗口挡住** / **落在任务栏上** /
   **主人在用鼠标** / **这个目标点过了** / **光标没到目标**。是什么原因就处理什么，
   **不要**一律"换个坐标再点一次"。
2. 被挡住 → 关掉那个飞框/面板（Esc、点别处、或者请主人挪一下），再重新**当场量**坐标。
3. 主人在用鼠标 → 等。
4. 已经点过一次 → **停**，先看清状态（`panel_state` / `screen_diff`），再决定要不要有新的证据、重新定位。
5. 都干净、还是没反应 → 用 `screen_diff` 复核，再用 `screen_look` 看清那一块到底是什么，
   或者直接问主人。**反复点同一个地方是最蠢的做法**，我不做。
