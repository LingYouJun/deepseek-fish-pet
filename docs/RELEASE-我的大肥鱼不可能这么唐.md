## 二、三个"假成功"的根因（这一版最值钱的部分）

### 1. `focus_window` 会**把可见窗口弄成不可见** ✗

**铁证**（对一个本来可见的计算器窗口调 Focus）：
```
调用前  hwnd=196736 visible=是      ← 窗口本来好好显示着
返回    "OK step1 show5,"           ← 它报告成功了
调用后  hwnd=196736 ★visible=否★    ← ★这套操作反而把它弄没了★
```
**机制**：`Focus()` 的最后一招是 `SW_MINIMIZE` → `SW_RESTORE` ✗，
而对 UWP 窗口，"最小化→恢复"恢复到的是它**之前的隐藏状态**；
★★ **而 Windows 允许把一个隐藏窗口设成"前台"** ★★
→ 所以 `GetForegroundWindow() == hwnd` **根本不能证明"看得见"** ✗

**修法**：新增 `Finish()`，**所有成功路径都经过它** ——
先补一次 `SW_SHOW`，再回读 `IsWindowVisible`；看不见就降级成 `step-showonly`
（部分成功 + 明确指引：改用 `click` 不要用键盘）。

### 2. 窗口"托不出来"的真凶是 **UWP 僵尸实例**

**现场**：三个计算器进程、三个窗口，其中一个是 `visible=否` 的僵尸 ✗；
而 `pickShown` 的兜底取 `list[0]` —— **恰好挑中那个僵尸** ✗
→ `focus_window` 反复对它操作 → 一直"显示了但抢不到前台" → 她以为窗口弄不出来 → 放弃。

**修法**：`pickShown` 改五级挑选（**只要 `visible=是` 就优先** —— 僵尸永远是 `visible=否`）；
新增 `kill_app`（只杀同名进程里较老的那些，保留最新一个，拒绝系统关键进程）。
★实测清掉僵尸后，`focusWindow` 立刻返回 `OK step4-minimize [前台已回读确认]`★ ✓

### 3. 抢不到前台 ≠ 失败

Windows 只允许**前台进程**改前台，而 UWP 应用的窗口属于 `ApplicationFrameHost.exe`，
跟她的进程不在同一个"前台锁"体系里 ✗。
→ 现在返回**部分成功**并告诉她：**窗口已经显示出来了，接下来用 `click` 点它、别用键盘** ✓
（键盘只发给前台窗口 ✗）

## 三、性能：输入从 49ms 降到 0.2ms

**基线**：每个动作 `spawnSync` 一个新进程 → ★12 次移动 592ms → 49.0ms/次★ ✗
（打游戏/连招根本做不出来）

**做法**：给 `Input.cs` 加 `serve` 常驻模式（`stdin` 一行命令 → `stdout` 一行 `OK`/`ERR`）。
★关键判断★：`input.js` 的返回值只表示"命令发出去没有"✗ ——
真正的"做没做成"由 `safedrive` 回读光标、截帧比对验证 ✓
→ 所以常驻模式下**只要写进 stdin 就算发成功**，不用等回复、不用改 API、不用动任何调用方 ✓

**三条安全规矩**：① 起不来/崩了 → 自动回退一次性 spawn ✓
② `PET_INPUT_ONESHOT=1` 强制回退 ✓ ③ 空闲 5 分钟自动收掉 ✓

**实测**：★12 次移动 2ms → 0.2ms/次（快 245 倍）★；
回退路径验证过（`PET_INPUT_ONESHOT=1` → `persistent:false` + 50.4ms/次 ✓）

**踩的坑**：`Serve()` 第一版写 `Split(' ', 2)`（限制 2 段）✗ →
`move 0.5 0.5` 变成 `["move","0.5 0.5"]` → `double.Parse` 报"输入字符串的格式不正确" ✓
（限制 2 段**只有 `type` 需要**）

## 六、程序强制（因为提示词不够）

★这一版最重要的认知★：**提示词提醒经常不够** ✗ ——

所以把最容易犯的两件事做成了**硬约束**：

### 1. 放大锚点守卫
- 连续放大 ≥4 次且中间没看整屏 → **拒绝这次调用**，要求先整屏定位 ✓
- 同一锚点「**宽度没变、高度在加**」→ **拒绝**，提示"你漏的多半是左右" ✓
  （★这正是她当时的签名★：高度 400→450→500，宽度纹丝不动 540）
- ★Electron 真跑验证★：模拟她今天的 4 个区域 → 第 1 次放行、第 2~4 次全部拦住 ✓；
  最后整屏 → 放行 + 守卫清零 ✓

### 2. 收尾目标核对
- 任务里有"找出「X」" → **收尾回复必须提到 X 或明说没找到** ✓，否则不让她收尾 ✓
